Strand 1 question 7. `title` is a prop: the parent owns it and passes it in, so TaskCard can only read and display it. `done` starts as a prop too, but TaskCard copies that starting value into its own state with `useState`. The checkbox can flip `done` because `setDone` updates state the card owns; nothing in TaskCard can rewrite `title`, because there is no setter for a prop.

Strand 2 question 4. React matches list items across renders by `key`, and it keeps each matched component's state. `task.id` stays with that task, so a reorder or a filter moves or removes the same card. The array index does not. `key={index}` names the slot, and after a reorder or filter that slot holds a different task. React then updates the old card in place: the title changes, but the checkbox state from `useState` stays behind, stuck to the previous task. Drop the first item and the cards below shift up by one index, so each surviving card inherits the state of the one that used to sit above it, and the last card's state is thrown away.

Strand 2 question 6. With `onChange`, typing updates `text` through `setText`, and the input shows what was typed. After removing `onChange`, the same keystrokes do nothing: the field stays empty. `value={text}` still locks the input to state, and that state stays `""` because nothing calls `setText`. React writes `""` back over each keystroke.

The Add click starts in `NewTaskInput`, on the button whose `onClick` is `handleAdd`. That component owns only the draft, `text`. The task list is `tasks` in `TaskBoard`, and `setTasks` stays there. `NewTaskInput` cannot update the list itself. What it can call is `onAddTask`, the prop `TaskBoard` passed in. That prop is `handleAddTask`, so `onAddTask(text)` runs back up in the parent and calls `setTasks` with a new array that ends in `{ id, title, done: false }`. `TaskBoard` re-renders and passes that array down to `TaskList`, which maps it and renders one more `TaskCard`. When `onAddTask` returns, `handleAdd` calls `setText("")`, clearing the draft the input owns. The child asked; the parent owned the list and made the change; the callback prop was the only path between them.
